## 1. 产品定位

**一句话**：VibeDesk 是本地优先（local-first）的 AI 交易 Agent 桌面应用——**多源真实行情对比 + 本地私钥钱包 + 多 Agent 并行 + AI 分析建议**，你的钱包、你的 AI（自带 API Key）、你的数据都在本地。

**与 Web 产品的区别**：类似 OpenCode / Windsurf 之于编程——用户自带 API Key，私钥与策略不出设备，数据源/策略/Agent 技能可插件化扩展，多个 Agent 可同时运行。

**MVP 边界（已确认）**：真实交易产品（真金白银），**黑客松交付 = 真实数据展示 + 多钱包管理 + 多 Agent 并行 + 信息管理 + Agent 分析建议**；真实下单执行列 P1（操作按钮占位）。

**内置默认交易模块（已确认）**：产品核心场景 = **监控股票在不同平台的差价**（TSLA/NVDA 等，聚焦股票、不用 BTC）；内置默认模块即"股票跨平台价差监控"，交易执行作为后续增强。

**核心展示点**：
1. **多源价格对比**：同一标的多平台实时价格统一展示（Robinhood / Hyperliquid / Binance）
2. **钱包中心**：多钱包本地私钥管理（跨平台加密、MetaMask 模式、多账号）
3. **多 Agent 并行**：多个交易/信息 Agent 同时运行、可管理

**核心原则**：
1. 本地优先：私钥、API Key、策略、数据默认留在用户设备
2. 安全透明：私钥加密存储、脱敏展示；Agent 推理与建议过程可视化
3. 多源多平台：CEX + DEX + 传统券商口径统一聚合，价差即机会
4. 插件化：数据源、策略、Agent 技能可插件化；Agent 可按需生成技能到本地
5. 国际化：OpenAI 兼容 API 协议（多模型/多语言），UI 文案 i18n 骨架
6. 跨平台：桌面端不绑定单一 OS（Electron 三端一致），存储方案零系统依赖

## 4. 核心展示点设计

### 4.1 多源价格对比页（R2，产品门面）

```
标列表（TSLA / NVDA / AAPL / BTC ...）
        │ 点击
        ▼
┌─────────────────────────────────────────────────┐
│ TSLA  Tesla Inc.              跨源价差: $2.86 (1.2%) │
│ ┌────────────┐ ┌────────────┐ ┌────────────┐     │
│ │ Robinhood  │ │ Hyperliquid│ │  Binance   │     │
│ │ $245.32 ▲  │ │ $247.18 ▲  │ │ $244.85 ▲  │     │
│ │ 24h +2.3%  │ │ 24h +1.9%  │ │ 24h +2.6%  │     │
│ │ ● 实时     │ │ ● 实时     │ │ ● 实时     │     │
│ └────────────┘ └────────────┘ └────────────┘     │
│  [Buy] [Sell]  （P0 占位 / P1 接执行）             │
│  [Ask AI to analyze] → 打开 Agent 分析建议         │
└─────────────────────────────────────────────────┘
```

要点：每源独立卡片（价格/24h/流动性/实时状态）；跨源价差置顶；某源无标的价格显示"不可用"且不参与价差。

### 4.2 钱包中心（R4，跨平台 + MetaMask 模式）

- 独立导航 + 独立视图；多账号列表（名称/链/地址缩略/余额/类型/状态）+ 分组 + 搜索
- 创建/导入向导：BIP39 助记词（**仅创建时展示一次**，要求抄写备份）、私钥、keystore；批量导入
- 安全模型：
  - **vault 加密文件**（如 `~/.vibedesk/vault.enc`）：AES-256-GCM；口令经 PBKDF2（高迭代）或 scrypt 派生密钥；口令不落盘
  - UI 全程脱敏（`0x1234...abcd`）；导出私钥/助记词需输入口令并二次确认
  - 会话内可"记住解锁"（内存缓存），重启需重新解锁
- 零系统依赖（不绑 Keychain/密钥环），三端一致

### 4.3 多 Agent 并行管理（R5）

- `AgentManager`（主进程）：注册/启动/停止/状态查询；每个 Agent 独立：id、名称、角色、systemPrompt、LLM 配置、工具集、运行状态（stopped/running/error）、日志
- 并行运行：每个 Agent 独立执行循环与上下文（互不阻塞）
- 内置 Agent 模板：
  - **Trading Analyst**：工具 = marketTools（get_price/compare_prices/get_candles/orderbook）→ 行情分析建议
  - **Info Collector**：工具 = information tools（read_news/read_tweets）→ 拉取并摘要新闻/推文，供其他 Agent 检索
- UI：Agents 视图（卡片列表：名称/角色/状态指示灯/LLM/最近活动；启停按钮；日志流；新建 Agent 向导）

### 4.4 信息管理模块（R6）

- `IMessageSourceProvider` 抽象：id、名称、type（rss / twitter / api）、fetchLatest()
- 信息源类型：
  - **新闻 RSS**：内置金融源（CoinDesk / Cointelegraph / 主流财经 RSS）
  - **Twitter/X**：经第三方聚合平台（默认 **Apify**：按量付费、有免费额度、MCP-ready、可定时调度；备选 Sorsa/Bright Data/Xpoz）
- 调度器：每源独立间隔定时拉取 → 本地存储（JSON 落盘，MVP 不引入 DB）
- Agent 工具：`read_news(源/关键词)`、`read_tweets(关注者/关键词)`、`search_information(关键词)`
- UI：Info Center 视图（信息源配置/启用/拉取状态/信息流列表/时间线）

## 5. 插件化架构设计

```
本地插件目录（用户可写）
├── plugins/data-sources/<id>/manifest.json + provider code
├── plugins/strategies/<id>/manifest.json + strategy code
├── plugins/skills/<id>/manifest.json + tool code
└── plugins/agents/<id>/manifest.json + agent template code

加载机制（主进程）
- 扫描插件目录 → 校验 manifest → 注册到各 Registry
- Agent 可通过工具"安装/创建"插件到本地（R12/R16）
```

- 数据源插件：`IMarketDataProvider`（已有）+ `ProviderManifest`（id/name/type/assetScope/authRequired/privacyNote/updateMode）
- 策略插件：`Strategy`（已有）+ 加载器
- Agent 技能：`ToolDefinition`（已有）+ manifest；Agent 可生成技能写入 plugins/skills
- Agent 模板插件：多 Agent 的"角色包"（systemPrompt + 工具集 + 默认配置）

| 来源 | 方案 | 鉴权 | 覆盖标的 | 备注 |
|------|------|------|----------|------|
